LLM Extraction & Evaluation

ExtractEval

Schema-driven framework that turns one YAML task definition into LLM extraction, scoring, and agentic routing — with zero code changes to add a new task.

The challenge

Extracting structured data from text with an LLM is easy to prototype but hard to trust. There was no clean way to evaluate extraction accuracy per field, compare models, or decide when output is confident enough to auto-approve.

What I built

A YAML-driven pipeline that handles extraction, type-aware scoring, a multi-model leaderboard, and a confidence-based router that sends results to auto-approve, review, or reject — with a validation-rules engine that catches malformed output before it ships.

LLM Cost Optimization

TokenLens

Token-cost calculator and optimization toolkit that prices an LLM request across 16+ models before you make it, then cuts spend with a three-lever optimizer and a semantic cache.

The challenge

LLM bills are opaque until the invoice arrives. You can't make good engineering decisions when you can't see whether a longer system prompt, a different model, or output-token limits would save you money at scale.

What I built

A toolkit that estimates tokens, prices the same request across models, shows savings from three optimization levers (trim, route, cap), and caches near-duplicate requests with a semantic embedder — all before the LLM call is made.

How I think

      
Architectural decisions, not just code

      
Hiring managers ask "why did you build it that way?" — here's a real example from ExtractEval's routing layer.

    

    

      
extracteval/routing.py

      
# The confidence router is the core design decision in ExtractEval.
# Instead of a binary pass/fail, it creates three lanes:
#   auto-approve  →  high-confidence, skip the queue
#   review        →  borderline, send to a human
#   reject        →  too unreliable to use
#
# Why this matters: a hard threshold wastes human time on
# output the model already got right. The three-lane router
# drove the auto-approved batch to 100% accuracy while
# sending only the uncertain fields to review.

def route(result, thresholds):
    min_conf = min(f.confidence for f in result.fields)

    if min_conf >= thresholds.auto_approve:
        return Route.AUTO_APPROVE

    flagged = [f for f in result.fields
              if f.confidence < thresholds.auto_approve]

    if min_conf >= thresholds.review:
        return Route.REVIEW(flagged=flagged)

    return Route.REJECT(reason="confidence below review floor")

    

    
The key trade-off: a higher auto-approve threshold means more human review but fewer escapes; a lower one means less review but more risk. Making this a YAML-configurable value, not a hardcoded constant, lets each extraction task set its own risk tolerance — an invoice might be strict (0.92), a content tag might be lenient (0.70).
